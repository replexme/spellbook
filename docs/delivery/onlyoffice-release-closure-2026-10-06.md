# ONLYOFFICE 교체 후보의 설치·AI·운영 추가 검증 — 2026-10-06

## 판단

LibreOffice 백업과 ONLYOFFICE 기본 엔진 교체를 유지하면서 실제 배포 경로, 새로 압축을 푼 AI 연결 프로그램, 실제 50장 문서와 운영 주소를 검사했다. 단위 검사로 끝내지 않고 설치 산출물에서 발견한 결함을 고쳤다. 공개 출시 승인은 여전히 보류다. 아래 통과 결과와 외부 실행 조건은 서로 대체할 수 없다.

증거는 `artifacts/onlyoffice-release-closure-20261006/`에 있다. 실제 문서, 계정 자료와 실행 기록은 Git에 포함하지 않는다. 이전 엔진 기능 94개와 단일 세션 100회 검사 기록은 `onlyoffice-local-switch-2026-10-06.md`에 보존한다.

## 설치 산출물에서 발견한 결함과 수정

기존 ZIP을 새 디렉터리에 풀고 빈 작업 디렉터리에서 네이티브 실행 파일을 직접 실행했다. 운영체제 전체가 새 기기인 것은 아니며, 기존 사용자의 실제 Codex·Claude 구독 로그인을 사용했다. 화면에 앱 창을 열지 않았다.

기존 설치 파일은 페어링과 모델 목록까지 성공했지만 문서 편집 API `/v1/local-turns`가 없어 404를 반환했다. 소스 검사 통과가 설치 파일의 동작 증거가 아니었던 것이다. 구형 산출물과 실패 기록을 보존하고 현재 소스로 연결 프로그램만 다시 패키징했다. 엔진·WASM은 재컴파일하지 않았다.

`/health`와 인증된 `/v1/models`에 실제 문서 편집 지원 여부를 추가했다. 구형 응답은 AI 실행 버튼을 활성화하지 않고 업데이트를 안내한다. 패키징 검사는 이 기능이 없는 실행 파일을 거절한다. 실제 페어링 뒤 구형 모델 응답을 재현한 브라우저 검사에서 안내 표시, 버튼 비활성, 편집 요청 0회를 확인했다.

## AI 화면 검토의 실제 실패와 수정

첫 새 패키지의 Claude 결과는 `reviewed: true`였지만 응답에는 이미지를 보지 못했다는 설명이 있었다. 이 결과를 화면 검토 통과로 인정하지 않았다. 실제 CLI 대화를 확인하니 전체 마스터·레이아웃 도형 자료가 MCP 응답 한도를 채워 스크린샷이 잘리고 파일 참조로 바뀌어 있었다. 제한된 문서 연결에서는 일반 파일 읽기를 허용하지 않으므로 그 참조로 검토를 복구할 수도 없었다.

내부 문서와 저장·권한 검사에는 원래 전체 상태를 유지한다. AI에만 현재 확인하는 슬라이드의 상세 자료와 나머지 슬라이드의 탐색 목록을 보낸다. 다른 슬라이드를 편집하려면 상세 관찰을 요청하도록 안내한다. 마스터 테마와 레이아웃 메타데이터는 유지하며 편집 대상이 아닌 템플릿 도형은 AI 응답에서 제외한다. Claude에는 이미지를 먼저 전달하고 문서 도구의 응답 한도를 지정한다. CLI가 자료를 잘라내거나 파일 참조로 바꾼 경우에는 성공 이벤트가 뒤따라도 화면 검토 완료를 거절한다. 같은 수정은 비공개 서비스의 Claude 연결에도 적용했다.

[Claude Code 공식 MCP 문서](https://code.claude.com/docs/en/mcp#mcp-output-limits-and-warnings)는 이미지도 전달 한도의 영향을 받음을 명시한다. 이번 결함의 직접 증거는 `claude-visual-failure-readback.json`이며, 수정 후 실제 이미지 전달 기록은 `claude-visual-fixed-readback.json`, 50장 결과는 `claude-50-visual-readback.json`이다.

실제 50장 문서의 약 1.5MB 상세 텍스트를 약 56KB로 줄였다. 해당 CLI 기록에는 1장 상세·49장 탐색 목록과 이미지가 있고 잘림 표시는 없다. 원본과 저장본의 나머지 49장 XML이 그대로인지는 별도로 대조했다.

## 구독 연결의 도구 경계

한 Codex 시도에서 `thread/start`가 30초 뒤 시간 초과됐고 같은 패키지의 재시도는 통과했다. 사용자 설정에 등록된 외부 MCP·플러그인도 구독 연결에 상속되는 별도의 경계 문제를 확인했다. 이 문제와 그 한 번의 시간 초과 사이의 인과관계가 완전히 확정된 것은 아니다.

빈 `mcp_servers` 설정은 기존 설정과 병합되므로 외부 서버를 제거하지 못하는 것을 실제 RPC로 확인했다. 문서 편집용 자식 프로세스에서만 플러그인·앱·훅을 끄고 상속된 MCP 서버 각각을 비활성화한 뒤 유효 설정을 다시 검사한다. 사용자 설정 파일을 수정하지 않는다. 비활성화를 확인할 수 없으면 편집 연결을 거절한다. [공식 설정 문서](https://learn.chatgpt.com/docs/config-file/config-reference)는 서버별 `enabled` 설정을 정의하고, [App Server 문서](https://learn.chatgpt.com/docs/app-server)는 유효 설정과 MCP 도구 목록의 읽기 API를 제공한다. 실제 고정 Codex 실행 파일에서 외부 서버 8개 모두 비활성, 노출 도구 0개를 확인했다. 시간 초과 실패 기록은 통과로 바꾸지 않는다.

## 실제 문서와 컨테이너

로컬 Linux의 고정 Node 22 이미지에서 Dockerfile 실행 단계가 복사하는 세 디렉터리만 읽기 전용으로 연결했다. 비특권 사용자, 추가 권한 없음, `node_modules`·자격 증명·고객 파일 마운트 없이 실제 편집기를 실행했다. 문서 열기·권한 거절·편집·저장·PDF·오프라인 편집·전체 재열기/복구·외부 파일 충돌 거절·모바일 미리보기의 10개 흐름을 통과했다. 이후 서버 프로세스를 즉시 종료하고 다시 시작한 상태에서 같은 브라우저의 미저장 편집 복구까지 11개 흐름을 통과했다. 최종 다단계 운영 이미지를 빌드하거나 배포했다는 뜻은 아니다.

최종 설치 파일 SHA-256은 `597b75a63eee5fb65d2a08e30bb38d26f20862359295a358bf43a43cc340c3ba`다. 새로 압축을 푼 실행 파일에서 실제 Codex와 Claude 각각으로 50장 문서의 메인 제목 `프로덕트 디자인 스프린트`만 `검증 완료`로 교체했다. 두 실행 모두 페어링·편집과 화면 검토·PPTX 저장의 4단계를 통과했고 캡처를 직접 확인했다. 부제목 `3일 버전`은 유지됐다. 두 저장본은 SHA-256 `dc618e01d091ded4719a019f51518a8e6b0f6032b46c9a6b8f987179233db360`로 동일하며 독립 OpenXML 검사는 각각 오류 0개다. 바뀐 ZIP 항목은 `ppt/slides/slide1.xml` 하나뿐이고 나머지 49장 XML은 원본과 바이트 단위로 같다. 최종 Codex 첫 검사는 Python ZIP 해제기가 보조 실행 파일의 Unix 권한을 복원하지 않아 실패했다. 아카이브 자체의 실행 권한을 확인하고 해제 코드에서 복원한 뒤 재검사했으며 실패 기록은 보존했다. 사용자 Codex 설정 파일 해시도 실행 전후 동일하다. 긴 제목 변경을 검사하던 Claude 실패 실행은 검사 정규식이 뒤 문장의 ‘문제 없음’을 이미지 누락으로 오인한 검사 코드 오류였으며 별도로 보존했다.

새 패키지에서 두 브라우저의 실제 페어링을 각각 승인한 뒤 다른 브라우저의 문서 작업을 읽으려는 요청은 404, 페어링 없는 요청은 403, 소유자의 취소는 200임을 확인했다. 이 검사는 운영 고객 계정 격리 전체를 대신하지 않는다. OS 파일 선택창은 진짜 OPFS 파일 핸들로 대체했으며 실제 네이티브 선택창 검사로 주장하지 않는다.

## 변환기 출처 검증

고정 x2t의 JS·WASM은 서명된 [v9.3.0+4 릴리스](https://github.com/agentbridges-ai/onlyoffice-x2t-wasm/releases/tag/v9.3.0%2B4)의 빌드 증명과 일치한다. GitHub 서명 워크플로, 태그, 소스 커밋 `5790fda684ac1a837f1ab92fcaaf4a0de9ec4ec1`, 호스팅된 빌드 실행자 조건까지 `gh attestation verify`로 확인했다. 릴리스 압축 SHA는 `94dd84fa067ebed4fde5763bd5592cb506ac61c3cd3c54cec84953535fb6c5c5`이다. 서명된 빌드 출처 검증이며 독립 재컴파일 증거는 아니다.

해시·글꼴·철자·압축 보조 WASM 4개는 공식 SDK 소스 아카이브의 원래 바이너리와 각각 일치한다. C++ 파일과 빌드 레시피 위치도 추적했다. 공통 레시피의 emsdk가 `latest`여서 이 네 바이너리를 만든 정확한 C++ 리비전·도구체인 대응은 확인하지 못했다. 바이너리 복사본끼리 같다는 것만으로 이 조건이나 라이선스 검토를 통과로 바꾸지 않았다. `publicReleaseAdmitted`는 `false`다.

## 운영에서 확인한 조건

- `spellbook.my`는 여전히 옛 Firebase 주소 `199.36.158.100`으로 해석되고 404를 반환한다. 실제 권한 DNS는 가비아이고 인증용 CNAME이 없다. Google 인증서는 현재 `PROVISIONING`과 `CNAME_MISMATCH`를 반환한다. 비위임 Cloud DNS에 레코드를 써서 해결됐다고 주장하지 않았다. 실제 변경값과 복구 순서는 비공개 저장소의 `docs/delivery/domain-records-2026-10-04.md`에 이미 있다.
- 제품 토큰으로 중앙 상품 목록을 조회하니 사용자 도메인과 직접 Cloud Run 주소 모두 404였다. 실행 중인 Accounts 소스는 `62ff5d2`이고 상품 목록 라우트를 추가한 `da771dd`는 그 뒤다. 새 API 배포가 필요하며 로컬 결제 상태 검사 16개와 제품 인증·결제 검사 43개는 통과했다. 상품은 후보, 결제 수단은 입점 진행 상태다. 실제 결제나 가격·환불 정책 승인을 만들어내지 않았다.
- 운영 로그인은 PKCE와 계정 선택을 포함한 중앙 로그인 주소로 이동하고, 잘못된 콜백 상태는 거절한다. 공개 서명 키도 응답한다. 실제 신규 고객 가입·세션·계정 분리·탈퇴·운영 복구를 이 HTTP 검사로 대체하지 않는다.
- 기존 Windows 11 Arm VM을 찾았지만 `vmrun start … nogui`는 암호 잠금 때문에 거절됐다. 실행 VM 0개를 확인했다. Windows PowerPoint를 열었다고 주장하지 않는다.
- macOS 앱의 로컬 코드 서명은 유효하지만 ad hoc 서명이며 Gatekeeper는 거절한다. 사용 가능한 인증서에는 배포용 Developer ID Application이 없다. 새 기기에서 서명·공증된 설치를 검증한 결과가 아니다.

배포·DNS 변경·실결제는 실행하지 않았다. 프로젝트의 ‘Paid Cloud Execution’ 규칙은 비용 발생 리소스와 배포 실행에 소유자의 해당 실행 승인을 요구한다. 현재 엔진 공개 승인도 보류 상태이므로 검토하지 않은 후보를 운영에 올려 검증 공백을 가리지 않는다. 다중 사용자 운영 경로와 실제 출시 산출물은 위의 조건을 충족한 후보에서 다시 검증해야 한다.

## 최종 기록

통과한 검사, 실패 분류, 최종 패키지 SHA, 현재 엔진 호스트 SHA, 소스 제공 압축과 정적 후보의 파일 대조, 이번 작업 소유 프로세스·컨테이너 정리는 `release-closure.json`에 기록했다. 최종 정적 후보 1,495개 파일과 소스 압축 351개 파일은 현재 원본과 모두 일치한다. 마지막 자동 검사는 핵심 Node 검사 605개, 공개 AI 검사 127개, 비공개 AI 검사 160개가 통과했고 양쪽 AI 타입 검사와 공개 경계 검사도 통과했다. 엔진/WASM 빌드와 유료 클라우드 실행은 0회다. 연결 프로그램 패키징과 작은 호스트 JavaScript 묶음만 로컬에서 생성했다. 기존 LibreOffice 복원 백업과 이번에 보존한 구형 설치 파일은 유지한다.
