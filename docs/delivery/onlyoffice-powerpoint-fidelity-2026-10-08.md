# ONLYOFFICE와 PowerPoint 화면 일치 개선

사용자 지시: 최근 교체한 ONLYOFFICE를 유지하고, PowerPoint를 항상 숨긴 백그라운드 상태에서 열어 캡처하며 기존 전체 사례의 차이를 조사하고 원인을 수정한다. 제품 코드와 회귀 검증은 공개 코어에서 작업한다. 고객 문서·캡처·개별 파일 식별자는 Git 밖의 평가 자료에 둔다.

## 완료 기준과 진행

- [x] 현재 엔진 선택과 문서 처리기의 미리보기 연결 확인. 편집은 ONLYOFFICE, 미리보기는 여전히 LibreOffice로 등록돼 있다.
- [x] 기존 PowerPoint 백그라운드 실행 도구 확인. 숨김·비활성 상태 확인, 소유 프로세스만 정리하는 절차를 유지한다.
- [ ] 전체 입력 목록 확정: 실전 30개, 공개 64개, 실제 오류 문서 원본/저장본, 정본 편집 명령 94개의 원본·저장 결과. 실패·미지원·입력 누락을 제외하지 않는다.
- [ ] 동일 입력의 PowerPoint PNG/PDF와 현재 ONLYOFFICE 화면을 새 실행에서 확보한다.
- [ ] 열기·변경 없는 저장·편집 저장·재열기의 차이를 분리하고 글꼴, 텍스트 배치, 표, 이미지, 마스터/레이아웃, 차트/SmartArt, 효과, 숨김/애니메이션 등 원인별 목록을 작성한다.
- [ ] 편집과 서버 미리보기에 같은 고정 ONLYOFFICE 렌더 경로를 적용한다. 파일 안전 검사와 변경 범위 검증을 유지한다.
- [ ] 확인된 화면 차이의 원인을 수정하고 같은 파일로 전후 및 전체 회귀를 검증한다.
- [ ] 중복 제품 화면과 필수 저작권 표시를 검토한다. 적용 배포판의 로고·법적 고지를 임의로 제거하지 않는다.
- [ ] 변경 파일과 원래 지시를 다시 검토하고 구현·실측·남은 차이를 각각 보고한다.

픽셀 차이 수치만으로 고객 품질을 통과 처리하지 않는다. 실제 캡처와 문서 구조를 함께 확인한다. 기존 LibreOffice 차이 분석은 조사할 기능 범위를 찾는 자료이며 현재 ONLYOFFICE의 결함 증거로 사용하지 않는다. PowerPoint의 macOS/Windows 차이와 고정 글꼴 환경도 별도 기록한다.
