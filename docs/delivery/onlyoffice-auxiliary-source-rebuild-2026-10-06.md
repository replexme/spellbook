# ONLYOFFICE 보조 모듈 소스 빌드와 제품 재검증 — 2026-10-06

## 범위

중단된 글꼴 빌드를 이어서 압축·철자 검사·해시·글꼴 보조 모듈 4개의 JS/WASM을 로컬에서 만들고, 대응 소스와 고정 컴파일러로 다시 같은 파일을 생성하는지 확인한다. 전체 편집 엔진이나 x2t를 다시 빌드하는 작업은 아니다. 기존 LibreOffice 복원 백업을 유지한다. 운영 배포나 공개 출시 완료를 이 로컬 결과로 대신하지 않는다.

## 실제로 발견하고 고친 문제

- 글꼴 빌드에 필요한 Hyphen 헤더가 없어 컴파일이 중단돼 있었다. 공식 저장소의 고정 커밋 `dcd90f0056cfbcbd2d389b7a13db45ddf5b0b98e`를 추가하고 아카이브 해시를 기록했다.
- FreeType 수정은 원본 소스에만 있고 실제 컴파일에 쓰는 graphics 복사본에는 빠져 있었다. 복사본에도 같은 패치를 적용하고 관련 중간 오브젝트를 무효화했다. 기존 배포 바이너리의 취약성을 확인했다고 주장하는 것은 아니다.
- 첫 4개 모듈 통합 검사는 `AscFonts.FT_CreateLibrary is not a function`으로 실패했다. 새 Emscripten이 비동기로 내보내는 함수가 준비되기 전에 wrapper가 함수를 연결한 것이 원인이다. wrapper 연결을 `onRuntimeInitialized` 안으로 옮기고 기존 SDK의 두 준비 알림을 유지했다. 이 변경은 제공 소스에도 들어 있다. [공식 초기화 계약](https://emscripten.org/docs/api_reference/module.html#Module.onRuntimeInitialized)을 확인하고 실제 편집·저장으로 검증했다.
- 추가한 Redo 검증에서 지원되지 않는 `redo_turn` API를 사용해 검사가 실패했다. 제품 버튼과 같은 `Send_UNO_Command` 요청으로 고쳤다. 실패 기록은 삭제하지 않았다.

- 최종 정적 후보의 첫 오프라인 복구 검사에서 `native_export_baseline_unstable`이 발생했다. 재실행 통과만으로 해결됐다고 판단하지 않았다. 생성한 원본 PPTX를 수집해 마스터의 `slidenum` 필드 표시가 `1`에서 `<#>`로 바뀌는 것을 확인했고, 고정 SDK 소스의 `word/Editor/PresentationField.js:189-230`이 같은 필드의 자동 표시로 두 값을 생성함을 확인했다. 기존 비교 규칙은 숫자만 인식했다. 템플릿의 명시적 슬라이드 번호 필드에서 `<#>`와 원래 파일의 `‹#›`를 같은 생성 표시로 처리하도록 보완했다. 날짜·일반 텍스트·필드 종류·서식·실제 슬라이드의 다른 값은 계속 비교한다. 새 회귀 검사는 수정 전 실패, 수정 후 통과했다. 수정한 정적 후보에서 로컬 파일·저장·PDF·오프라인 재열기·미저장 복구·충돌 거절·모바일의 10개 흐름이 통과했다.
- 프로그램 캐시 식별값은 파일 개수 등의 요약 자료와 호스트 파일에만 의존해 보조 모듈 교체를 반영하지 못했다. 전체 배포 manifest 해시를 사용하도록 바꿨다. 보조 모듈 해시만 바꿔도 캐시 식별값이 달라지는 회귀 검사로 확인했다.

## 소스와 생성 파일의 연결

컴파일러는 Emscripten 4.0.11, linux/amd64 이미지의 고정 digest다. x2t의 수정 core 소스, build_tools, Hunspell·HarfBuzz·Brotli·OpenSSL·Hyphen 의존성의 커밋과 아카이브 해시를 기록했다. 실제 수정·헤더 생성·wrapper를 포함하고 미사용 기존 바이너리를 제외한 선호 소스 스냅샷을 `auxiliary-preferred-source.tar.gz`로 제공한다. 오브젝트 캐시, 배포 바이너리, 고객 문서와 시스템 폰트는 소스 스냅샷에서 제외했다.

`rebuild-auxiliary.py`는 소스 압축의 SHA-256을 확인한 뒤 빈 디렉터리에서 네 모듈을 컴파일하고, JS/WASM 8개 각각이 기록된 해시와 정확히 같아야 성공한다. 컴파일 컨테이너는 로컬에서 네트워크 없이 실행하고 종료 후 제거한다. 기존 선택된 엔진을 자동으로 바꾸지 않는다. 빌드 기록은 `sources/auxiliary-build-receipt.json`, 실행 방법은 `sources/auxiliary-BUILD.md`에 제공한다.

소스 묶음의 추가 검사에서는 원본에 함께 들어 있던 미사용 데스크톱 바이너리를 발견했다. 파일 확장자뿐 아니라 실제 파일 헤더로 검사해 1,473개를 제외한 최종 소스 묶음으로 다시 깨끗한 빌드에서 8개 출력이 같음을 확인했다. 첫 번째 묶음으로 통과했던 결과를 지우지 않고, 최종 제공 소스의 검증과 구분해 보존한다.

배포 검사도 보강했다. 재현 완료 표시가 있으면 대응 소스 압축, 고정 컴파일러, 재현 결과 상태, 4개 JS/WASM 쌍의 해시를 함께 검사한다. 단순히 플래그만 켜거나 한 쌍을 빠뜨리거나 다른 출력 해시를 쓰면 거절한다.

## 검증 결과

- 빈 작업 디렉터리와 캐시 없는 로컬 컴파일에서 보조 모듈 4개, JS/WASM 8개의 해시가 모두 일치했다. 대응 소스 압축 SHA-256은 `d1dda6ec815839d898375f7a91b0e87f9101b404d15957b58545274a017cd58c`이다. 결과는 `source-only-clean-reproduction-v2/reproduction.json`에 있다.
- 새 모듈을 사용하는 정식 호스트의 전체 기능 94개가 통과했다. 실제 네이티브 변경, 새 저장 파일의 독립 형식 검사, 원본과 정확히 같은 Undo, 수정본과 정확히 같은 Redo를 확인했다. 새 형식 오류와 페이지 오류는 0이다. `source-built-host94-final/report.json`에 전체 사례를 보존한다.
- 관련 자동 검사 516개가 모두 통과했고 건너뛴 검사는 없다. 재현 도구의 입력 거절 5개도 확인했다. 소스 압축 변경, 고정되지 않은 컴파일러, 다른 플랫폼, 빠진 출력, 허용되지 않은 출력 경로는 디렉터리나 컨테이너를 만들기 전에 거절됐다. Python `-O`에서도 적용됐다.
- 최종 후보 배포 파일 1,764개, Brotli 압축 281쌍, 제공하는 정적 파일 1,503개와 호스트 소스 354개를 읽어 대조했다. 최종 배포 manifest SHA-256은 `35e9594f3a24b38f99e3acc9dcdadfc0ed41f577e8f452e303068d4da525a633`다. `source-built-static-readback-v4.json`과 `source-built-final-cohort-identity.json`은 최종 실행 파일이 94개 검사와 같은 파일임을 기록한다.

실제 50장 파일의 구조 작업 10개도 최종 호스트에서 모두 통과했다. 추가·복제·삭제·이동·크기·레이아웃·이름·숨김·전환·메타데이터 변경마다 저장본의 독립 형식 검사, 원본 그대로 Undo, 수정본 그대로 Redo, 저장 파일을 다시 열었을 때 전체 슬라이드 상태의 일치를 확인했다. `source-built-real50-structure-final/report.json`이 근거다. `source-built-local-workflow-final/local-report.json`에는 로컬 파일·PDF·오프라인 재열기/복구·충돌 거절·모바일의 10개 흐름 통과 결과가 있다. 파일 선택창은 실제 OPFS 파일 핸들로 대체했으며 운영체제의 네이티브 선택창을 검증한 것은 아니다.

단일 네이티브 세션을 다시 시작하지 않고 관찰·편집·Undo·Redo·파일 저장을 섞어 100회 실행했고 모두 통과했다. 저장본 11개를 독립 형식 검사했으며 예상하지 못한 요청 실패는 0이다. `source-built-endurance100-final/report.json`이 근거다. 새로 압축을 푼 macOS 연결 프로그램을 창 없이 실행하고 실제 Codex 구독(GPT-6-Astra)과 Claude Code 구독(Sonnet)으로 같은 50장 파일의 제목을 수정·화면 검토·저장했다. 두 실행 모두 통과했다. 각각 저장본의 독립 Open XML 형식 검사가 유효했고, 전체 ZIP 내용에서 `ppt/slides/slide1.xml`만 변경됐으며 다른 49장 XML과 나머지 파일은 바이트 단위로 같았다. 두 최종 캡처를 직접 확인했고 사용자 Codex 설정 해시도 실행 전후 같았다. `source-built-codex50-final/report.json`, `source-built-claude50-final/report.json`, `source-built-ai-saved-readback.json`에 근거를 보존한다. 과거 전체 실패·복구 계약 검사는 이번 후보의 통과 결과와 합산하지 않는다. 이번 후보에서는 전체 실패·복구 계약 15단계 검사를 네 기능에 대해 추가로 확인했으며, 전체 94개에 같은 15단계를 재실행한 것은 아니다.

## 보존 자료와 복원

원래 선택된 배포 파일 중 교체한 파일과 이전 manifest는 `selected-before-auxiliary/`에 보존했다. 기존 LibreOffice 독립 복원 백업도 유지한다. 첫 글꼴 런타임 실패, 지원되지 않는 Redo 검증 실패, 중단한 느린 전체 계약 검사 기록도 삭제하지 않았다. 소스 압축에는 고정 공개 원본의 PPTX 시험 자료 8개가 포함되며 각각 원본 해시와 같음을 확인했다. 사용자 문서·설정·컴파일 캐시·Emscripten 설치는 포함하지 않는다.

로컬 컴파일 컨테이너는 매 모듈 종료 후 제거했고 임시 컴파일러 이미지와 이번 작업에서 켠 Colima를 종료·제거했다. Docker context는 기존 `default`로 복원했다. 고객 문서, 계정 자료와 실행 캡처는 Git에 포함하지 않는다.

## 남은 출시 조건

이번 확인에서도 `spellbook.my`는 가비아 권한 DNS의 기존 Firebase IP를 가리켜 404를 반환했고 인증서 CNAME이 없었다. macOS 코드 서명 목록에는 Developer ID Application 인증서가 없었다. 중앙 상품 API의 운영 배포, DNS 변경, 앱 서명·공증 및 잠긴 Windows PowerPoint 환경의 검증은 별도 조건이다. 필요한 DNS 변경값과 중앙 API 배포 계획은 기존 기록에 있다. 과금 리소스 생성과 배포 실행에는 프로젝트 규칙에 따른 해당 실행 승인이 필요하다.

공개 출시 승인 상태를 로컬 검사 통과만으로 바꾸지 않는다. 공개 배포의 소스·라이선스 검토와 운영 증거도 별개다.
