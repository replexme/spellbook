## UI 회귀의 원인과 수정

초기 캡처 중 일부는 제품의 상단 바와 AI/버전 패널을 우회하는 `/local` 시험 화면이었다. ONLYOFFICE에 한국어 설정과 실제 파일명을 전달하지 않아 영어 메뉴와 `service.pptx`도 나타났다. 이는 엔진 교체의 필수 결과가 아니라 통합 누락이었다.

로컬 화면에 기존 제품의 디자인 토큰, 버튼, 상단 바, AI 패널과 하단 입력 구조를 연결했다. 한국어와 실제 파일명, 다른 이름으로 저장한 뒤의 새 파일명까지 네이티브 편집기에 전달한다. 모바일은 기존 제품과 같이 슬라이드 미리보기·이전/다음 이동·AI 편집을 제공하고, 직접 편집은 큰 화면에서 한다. 기본 편집기 메뉴 자체는 ONLYOFFICE의 네이티브 UI이며 LibreOffice 메뉴와 픽셀 단위로 같다는 뜻은 아니다.

초기 모바일 검사에서 가로 넘침만 검사해 빈 화면을 놓쳤다. 실제 캡처로 이를 발견하고 네이티브 슬라이드 이미지와 모바일 패널을 연결했다. 오프라인 최초 실행의 한국어 글꼴 미리보기 누락도 확인해, 고정 글꼴 목록과 미리보기를 서비스 워커 설치 때 캐시에 넣도록 수정했다. 컨테이너 실행 단계의 공용 CSS 복사 누락도 수정했다. 이 기록을 확정한 시점에는 컨테이너 실행 증거가 없었다. 이후의 실제 Linux 실행과 설치 파일 재검증은 `onlyoffice-release-closure-2026-10-06.md`에 기록한다.

## 출시 판단과 남은 조건

후속 실제 검증과 설치/AI 결함 수정은 [추가 검증 기록](onlyoffice-release-closure-2026-10-06.md)을 따른다. 아래는 이 문서 확정 당시의 보류 조건이며, x2t 서명된 출처와 실제 컨테이너/설치 검사를 추가 기록으로 구분한다.

로컬 기본 엔진 교체와 공개 출시 승인은 별개다. `publicReleaseAdmitted`는 `false`다. 제공받은 보조 WASM 소스/바이너리 일치 일부는 확인했지만, 선호 수정 소스의 정확한 C++ 리비전·도구체인과 변환기 전체 바이너리의 재현 가능한 생성 관계를 입증하지 못했다. 소스 압축 파일을 제공하는 것만으로 이 조건이 해결됐다고 주장하지 않는다.

새 후보로 실제 운영 SSO·고객 계정 격리·실제 결제·운영 저장/장애 복구·실제 컨테이너·새 기기 서명 설치·Windows PowerPoint 및 넓은 문서군의 결과는 아직 없다. 운영 `/ready`와 HTTP 200은 기존 서비스 응답 확인이며 이 조건을 대신하지 않는다. 승인 없는 배포나 유료 리소스 생성을 통해 이 공백을 메우지 않았다. 따라서 현재 결론은 로컬 교체 후보이며 공개 출시 완료가 아니다.

## 정리

이번 작업이 만든 검증 DB 컨테이너와 익명 볼륨, 새 PostgreSQL 이미지를 삭제했고, 시작했던 Colima를 중지한 뒤 Docker context를 기존 default로 복원했다. 다른 프로젝트 이미지와 기존 앱/공유 AI 서비스는 건드리지 않았다. 문서가 없는 상태의 이번 작업 소유 숨김 PowerPoint도 종료했다. 검증 서버와 임시 배포 조합 디렉터리도 종료·정리했고, 선택 배포본과 독립 백업, 성공·실패 증거는 보존한다.

`final-static-readback.json`에서 최종 후보 `static-delivery-clean-final`의 1,495개 파일과 소스 압축 파일의 351개 소스를 다시 읽어 해시/내용을 확인했다. 100회 검사 때의 호스트 묶음 세 개는 그대로이며, 차이는 따로 검증한 CSS·모바일 모듈과 소스 제공 파일이다. 작업공간/Compose/Docker 설정도 소스에 포함했고 macOS 보조 메타데이터는 제외했다.
